# GUI-процессы для agterm

Цель: проект, отдельная задача и запуск Claude открываются через палитру и кнопки,
без ручного ввода команд git. Основа: agterm 0.39.1+, Python 3.10+, zsh, git, jq,
curl и локальный Claude Code. Для выбора каталогов нужен `fd`.

Установка из корня kit: `make install-gui`. Она также устанавливает обычные wt/ask.
Только cookbook и GUI: `python3 workflows/install.py`.
Без загрузки из сети: `python3 workflows/install.py --source /path/to/agterm-checkout`.
Checkout должен содержать файлы с хешами из `recipes.lock.json`.

После установки: `agtermctl keymap reload`. Новые skills и hooks загружаются в новой
сессии Claude. Существующие Orca hooks, настройки и чужие команды сохраняются.
Повторная установка не создаёт дублей. Перед заменой настройки сохраняется `.bak.<время>`.
Ошибка записи вызывает откат уже изменённых настроек, скачанный кеш остаётся.

| Действие | Где найти | Результат |
|---|---|---|
| Проект: открыть с Claude | Палитра agterm | Выбор репозитория из wt.conf, новая сессия Claude |
| Задачи и worktree | Ctrl+Shift+W, палитра | Выбор проекта, поиск ветки, создание, запуск, удаление |
| Недавние агенты | Палитра | Помечает сессии с недавним статусом |
| Flagged dashboard | Палитра | Сетка помеченных сессий |
| Claude Resume | Палитра, сохраняется прежняя клавиша | Выбор локального разговора Claude |
| Выбрать каталог | Палитра | Выбор пути и вставка в текущий ввод, без Enter |
| Новый компаньон | Палитра | Именованная сессия рядом с текущей |
| webrev | Skill Claude | HTML-рецензия документа, заметки возвращаются агенту |
| agdoc | Skill Claude | Документ в HTML поверх терминала |

Контекст сессии подсказывается Claude при отправке промпта. После завершения задачи,
когда агент очистил строку контекста через agtermctl, hook предлагает продолжить,
очистить или закрыть сессию. По умолчанию выбрано продолжение.
Clear сбрасывает оба разговора split, Close затрагивает компаньонов. Публикацию HTML
в интернет kit не запускает: agdoc делает это только по отдельному запросу.

## Конфиг и ограничения

Проекты и root берутся из `~/.config/agterm-kit/wt.conf`; личных путей в коде нет.
`~/.config/agterm-kit/workflows.conf`: `model = opus`, `recent_minutes = 30`.
Модель применяется к запуску Claude и генерации названий разговоров. Внешних LLM API нет.

Создание использует существующий wt, обновляет origin и запускает агента в новой сессии
в окне вызова. При отказе терминала созданный worktree остаётся доступен в списке.
Одноимённые клоны можно открывать по полному пути, но создание для них блокируется:
схема wt `<root>/<имя репы>/<ветка>` не различает такие клоны.

Удаление требует точного имени ветки. Оно разрешено только внутри root, для закрытой
в agterm, чистой, доступной ветки с коммитом, сохранённым в свежем origin. Уникальные
игнорируемые файлы также блокируют удаление. Ссылки .venv/node_modules и неизменная копия
settings.local.json, перенесённые wt, допускаются. Локальная ветка сохраняется.
Не используйте удаление одновременно с записью в тот же worktree из другого приложения:
git не даёт общей блокировки файловой системы. Процессы вне agterm kit не обнаруживает.

Журнал действий: `~/.local/state/agterm-kit/gui.jsonl`, время/action/outcome, без путей
и текста задач. Сбой журнала не меняет результат уже выполненной операции.

## Оформление и проверка

Панель задач использует палитру JetBrains New UI Dark, системный шрифт и локальный
JetBrains Mono при наличии. Никаких CDN. Вопросы ask наследуют тему agterm.
Для терминала выбрана встроенная JetBrains Islands Dark. Live sessions применяется
после перезапуска agterm; kit не закрывает рабочие сессии автоматически.

`make lint` и `make test` работают без сети и настоящего agterm. Тесты используют
изолированный HOME, настоящие локальные git-репозитории и поддельный agtermctl.
`make eval-gui` требует установленный cookbook и локальный Claude, вызывает настроенную
модель и оценивает шесть решений по инструкциям webrev/agdoc. Порог 100%, отчёт в tmp.
Этот eval проверяет решения агента, а не рисование страницы или весь интерактивный цикл.
Платные evals не входят в pre-commit и CI.

Перед выпуском GUI вручную проверяется в agterm: обновить список, открыть создание,
ввести недопустимую ветку, проверить сохранение ввода и ошибку, отменить без изменения git.
Для новой темы сравниваются основной список, диалог и узкое окно. Это фиксированный
чеклист, чтобы не повторять ошибку оценки интерфейса только по исходному HTML.

Откат: восстановить нужный `.bak.<время>` для keymap/settings и перезагрузить keymap,
удалить только созданные kit ссылки webrev/agdoc. Рабочие каталоги и ветки не меняются.
