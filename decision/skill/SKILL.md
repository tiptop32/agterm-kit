# Разбор журнала решений

Журнал ведёт CLI `agterm-decision` (проверьте, что он на PATH; ставится симлинком
в `~/.local/bin` из клона agterm-kit). Скилл логики не содержит: только вызывает
команды CLI и показывает их вывод пользователю. Команды печатают JSONL.

## Шаги

1. Запустите `agterm-decision open` — он печатает неразобранные записи: решения
   без вердикта и вопросы без ответа за 14 дней (свежие сверху). Можно сузить
   выборку: `--repo <репа>`, `--since 30d`.
2. Покажите записи пользователю таблицей: `id`, `repo`, дата (`ts`), `text`,
   `why`. Указывайте короткие префиксы `id` — их достаточно для последующих команд.
3. Спросите по каждой записи (или пачкой):
   - решение — «оставить, изменить или откатить?»;
   - вопрос — ответ пользователя.
4. Закройте записи:
   - `agterm-decision mark <id> keep|change|revert --note '<заметка>'` — только для
     `kind: decision`;
   - `agterm-decision answer <id> --text '<ответ>'` — только для `kind: question`.
5. Перепроверьте: снова `agterm-decision open` — разобранные записи должны уйти.

## Вердикты change и revert

Вердикт пользователя ставится командой `mark`, но самого изменения кода он не
делает. После `change` или `revert`:

- предложите правку и, если пользователь согласен, внесите её в текущей сессии;
- либо, если правка выходит за рамки сессии, предложите follow-up задачу через
  диспатчер (AgentDispatch) — сформулируйте её из `text`/`why` записи и заметки.

Не отмечайте `keep`, если пользователь только обсудил решение.

## Если agterm-decision недоступен

Сообщите пользователю, что CLI не установлен, и укажите раздел «Журнал решений»
в README agterm-kit с командой установки.
