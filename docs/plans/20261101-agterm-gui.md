# Переход с Orca на agterm с Claude и графическими действиями

## Goal
Открывать проекты и задачи с Claude, выбирать worktree, читать и комментировать документы,
наблюдать агентов и завершать задачи через GUI agterm. Создание и безопасное удаление worktree
не требуют ручного ввода shell-команд. Результаты действий и оценки оставляют журнал.

## Context
В kit уже есть wt и HTML-вопросы ask. На машине agterm 0.39.1, Claude с model=opus,
статусы агентов, старые команды выбора разговоров и flagged dashboard. Существующие
настройки, сторонние хуки и сочетания клавиш сохраняем. Личные пути остаются в wt.conf.
Стандартные git, zsh, Python stdlib и нативный HTML bridge достаточны; новый фреймворк не нужен.
Рецепты берём из umputun/agterm с фиксированным commit и SHA-256 каждого файла.

## Scope
- In: project launcher, GUI worktree, webrev, agdoc, recent agents, flagged dashboard,
  conversation picker с opus, native directory picker, named companion, context nudge,
  end-of-task offer; проверка встроенных статусов и Live sessions.
- Out: публикация HTML в интернет без отдельного запроса, новые TUI, удаление Orca,
  перенос существующих разговоров Orca, внешние LLM API, автоматическое завершение процессов.

## Implementation

### Task 1: воспроизводимая установка cookbook
- Files: workflows/recipes.lock.json, workflows/install.py, workflows/run.py,
  workflows/workflows.conf.example, install.sh, tests/workflows.bats.
- Change: загрузка только закреплённых файлов с проверкой SHA-256 и повторным использованием
  кеша; установка навыков webrev/agdoc; управляемый блок палитры и хуки Claude без дублей;
  атомарная запись, сохранение прав, симлинков и бэкапов. Основной агент Claude, модель opus.
- Verify: изолированный HOME, установка из локальной копии upstream, повторная установка,
  сохранение чужих команд/хуков и отказ при испорченном файле или блоке.

### Task 2: графическое управление worktree
- Files: wt/agterm-worktrees, wt/gui-bridge.zsh, wt/worktrees.html, tests/worktrees.bats.
- Change: использовать конфиг и создание wt через контракт JSON, без дублирования создания
  веток. Репозиторий выбирается по полному пути. Отмена ничего не меняет; ошибки видны в GUI.
  Единая HTML-панель в стиле JetBrains New UI Dark: палитра #1e1f22/#2b2d30,
  компактные строки веток, один основной action, создание и удаление в диалогах.
  Удаление требует явного подтверждения, отказывает для основного клона, грязного дерева,
  локальных коммитов без подтверждённой сохранности и открытых терминальных сессий.
- Verify: настоящие локальные git-репы, поддельный agtermctl, имена с пробелами/кавычками,
  недопустимые ветки и пути, ошибки fetch/session new, удаление и отмена.

### Task 3: проверка полного рабочего сценария
- Files: evals/gui-workflows.py, workflows/README.md, README.md, Makefile,
  .pre-commit-config.yaml, .github/workflows/ci.yml.
- Change: gate-тесты на публичных границах, отдельный периодический eval локального Claude
  для решений webrev/agdoc (вопрос, правка, отмена, восстановление, локальная страница,

- Verify: пользователь выбирает проект, создаёт задачу, открывает Claude; HTML-рецензия
  возвращает заметку; отмеченные агенты отображаются; отмена/ошибки сохраняют работу.

### Task 4: установка на машине и завершение
- Files: настройки пользователя вне репозитория (с бэкапами).
- Change: после зелёных проверок установить интеграции, перезагрузить keymap без закрытия
  рабочих сессий, проверить состояние Live sessions и статусов; не перезапускать agterm
  с текущими задачами автоматически. Свежий независимый review, оценка, commit и push.
- Verify: ноль диагностик keymap, наличие навыков и хуков, рабочие GUI-действия и evidence в /tmp.

## Final verification
- make lint
- make test
- make eval-gui
- git diff --check

Общий test lane нужен из-за изменений установщика, wt-контракта и интеграции нескольких утилит.
Платный eval запускается локальным Claude с лучшей настроенной моделью; порог 100%.

## Risks and rollback
Рецепты являются snapshots; обновление commit и хешей проходит review и проверки.
Установщик не заменяет сторонние skills молча. Старый keymap и settings доступны в бэкапах.
При отказе agtermctl worktree остаётся зарегистрированным и доступным из GUI после обновления.
Удаление не использует force и не закрывает процессы. Live sessions требует перезапуска
agterm для вступления настройки в силу; перезапуск выполняет пользователь.

## Результат проверки 2026-11-01

Реализованы задачи 1–4, кроме успешного платного прогона: локальный Claude Opus
вернул 429, обе учётные записи недоступны по квоте. Eval добавлен и запущен,
результат не считается зелёным. Модель не понижалась.

Тема JetBrains Islands Dark применена в agterm. Панель использует JetBrains New UI
Dark; вопросы ask наследуют цвета терминала. В настоящем HTML overlay проверены
обновление списка, диалог создания, ошибка недопустимой ветки с сохранением ввода
и отмена. Автоматические git-тесты проверяют создание, восстановление после отказа
терминала, удаление и защиту данных. Независимое review: blockers не найдено.

Три прохода проверки: локальные контракты и регрессия установщика; совместимость
CLI и тесты upstream; настоящий интерфейс agterm. Свежий ключевой список не имеет
диагностик. Узкое окно 760×720 проверено в настоящем agterm: элементы перестраиваются,
пути сокращаются, кнопка запуска доступна. Исходный размер окна восстановлен.
Платный eval требует повторения после сброса квоты и не считается успешным.
Финальные логи и evidence находятся в /tmp/agterm-gui-evidence.
