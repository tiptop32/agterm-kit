# Диалог не открывается после перезапуска agterm

Симптом: `ask_user` возвращает `no such session`, хотя терминал открыт.
Причина: MCP-сервер живёт дольше сессии agterm и наследует старый ID.

1. Сохранить сообщение об ошибке без текста вопроса.
2. Проверить доступность `agtermctl window list --json`.
3. Получить `tree --json --window <id>` для каждого открытого окна.
4. Найти старый ID в деревьях. Если он существует, причину искать в ошибке открытия.
5. При отсутствии старого ID сопоставить стабильный `AGTERM_PANE_ID` с `surfaces[].paneID`.
6. Если панель исчезла, найти точное совпадение cwd процесса MCP и локальной сессии.
7. Разрешить только одно совпадение. При нуле, нескольких или неполной инвентаризации
   остановиться; не использовать active и не выбирать окно по фокусу.
8. Использовать новый ID при открытии, чтении результата и очистке своей страницы.
9. Запустить регрессионные проверки: `bats --filter 'stale session' tests/agterm-ask.bats`.
10. Запустить `evals/ask-session.sh` в каталоге нужной сессии и ответить в живом диалоге.
    После успешного round-trip сохранить путь отчёта, не содержимое ответа.

Шаги 2–8 выполняет `ask/resolve-session.py`, вызываемый ядром после ошибки устаревшего
адреса. Обычные ошибки overlay (занят слот, закрытие, отказ доступа) восстановление не
запускают. Если потеряны и ID панели, и прежний cwd, перезапустить MCP-клиент из нужной
сессии. Другой открытый диалог не закрывать.
